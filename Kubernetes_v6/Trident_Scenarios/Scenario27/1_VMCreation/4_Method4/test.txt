The blocker is not clone strategy anymore.
It is source/target format compatibility:

Source PVC is Block (iSCSI block device).
Target PVC is Filesystem on NFS.
CDI clone copy does not perform a block-to-filesystem conversion during PVC clone.
So even with cloneStrategy: copy and cdi.kubevirt.io/cloneType: copy, DV stays CloneInProgress with temp PVC created but target PVC pending.

What works:

Block -> Block clone (your iSCSI -> iSCSI test succeeded).
Filesystem -> Filesystem clone.
Same or compatible storage semantics for clone path.
What does not work directly:

Block source PVC -> Filesystem target PVC (your iSCSI Block -> NFS Filesystem case).

Export source Block PVC and convert to qcow2, then serve over HTTP:

cat <<'EOF' | kubectl apply -f -
apiVersion: v1
kind: Pod
metadata:
  name: pvc-qcow2-exporter
  namespace: sc26-alpine-c
  labels:
    app: pvc-qcow2-exporter
spec:
  restartPolicy: Never
  containers:
  - name: exporter
    image: quay.io/kubevirt/container-disk-v1alpha:latest
    command:
    - /bin/sh
    - -c
    - |
      set -e
      mkdir -p /data
      qemu-img convert -f raw -O qcow2 /dev/srcdisk /data/src.qcow2
      python3 -m http.server 8080 --directory /data
    volumeDevices:
    - name: src
      devicePath: /dev/srcdisk
    ports:
    - containerPort: 8080
  volumes:
  - name: src
    persistentVolumeClaim:
      claimName: alpine-boot
---
apiVersion: v1
kind: Service
metadata:
  name: pvc-qcow2-exporter
  namespace: sc26-alpine-c
spec:
  selector:
    app: pvc-qcow2-exporter
  ports:
  - port: 8080
    targetPort: 8080
EOF
